# 単元設計チームの計画（特支・単元設計室）

担任の要望（2026-08-22）:
単元の各時間ごとの問いを作る／各時間のゴールと単元のゴールを決める／
学習指導要領を基に評価用ルーブリックを作る／必要な資料やデータを集める／板書計画を作成する。

これを1チームで通しでやる。既存の「特支・同時異教材室」は**1時間分の教材**を作るチームで、
こちらは**単元まるごと**を設計するチーム。出口が違うので分ける。

---

## 1. 何が難しいか（先に書く）

この5つは並列に見えて、実は**依存関係がある**。

```
単元のゴール ──┬─→ 各時間のゴール ──┬─→ 各時間の問い ──→ 板書計画
               │                     └─→ ルーブリック
               └─→ 必要な資料・データ
```

ゴールが決まる前に問いは書けないし、問いが決まる前に板書は割り付けられない。
既存のチーム構造はサブエージェントが**同時に**動くので、
そのまま5人に配ると、互いに噛み合わない5つの成果物が出てくる。

だから**ゴールはリード（授業デザイナー）が自分で決め、担任の承認を取ってから**、
残りをサブに並列で投げる。承認ゲートが1回入る。

## 2. チーム構成（5体。`MAX_AGENTS = 5` に収まる）

| 役 | 担当 | モデル |
|---|---|---|
| リード「単元デザイナー」 | 実態を読む／**単元のゴールと各時間のゴールを決める**／担任の承認を取る／4人の成果を1つにまとめる | 既定 |
| サブ1「問いづくり」 | 各時間の中心発問と、児童の段階別の問い直し | Haiku |
| サブ2「評価」 | ルーブリック（下書き）。**一次資料の記述だけを根拠にする** | 既定※ |
| サブ3「資料集め」 | 実践事例・素材・データ。**web_search を使う** | 既定※ |
| サブ4「板書」 | 板書計画。図として描く | Haiku |

※ 評価と資料集めは根拠の扱いが厳しいので Haiku ではなく既定モデル。
ここはコストより正確さを取る。1回あたりの費用は同時異教材室より高くなる（後述）。

## 3. 学習指導要領をどう扱うか

**記憶から書かせない。** 自立活動の区分・項目と同じ扱いにする。
ここを緩めると、それらしい文言のルーブリックが出てくるが、根拠がない。

二段構えにする。

1. **担任が置いた一次資料を最優先で読む** — `00_共通/学習指導要領/` に教科・学年ごとに置く
   （例: `00_共通/学習指導要領/算数_第2学年.md`）。無ければ次へ
2. **web_search で `mext.go.jp` に限定して探す** — `allowed_domains` で告示・解説のドメインだけに絞る。
   見つからなければ「該当箇所を確認できません。一次資料をフォルダに置いてください」と返す

**推測で書いた場合は必ず「要確認」を付ける**（S7）。ルーブリックには必ず「下書き」と明記する（S4）。

### 特別支援での読み替え（担任に確認が要る）

同じ「2年の算数」でも、根拠を
(a) 小学校学習指導要領（当該学年）に置くのか、
(b) 下学年の目標・内容を適用するのか、
(c) 特別支援学校（知的障害）の各教科の段階に置くのか
で、ルーブリックの記述語が根本的に変わる。**ここは推測できない。**

→ `00_共通/評価の根拠.md` に担任が方針を1行書き、リードが毎回読む形にする。

## 4. 資料・データ集め

`web_search` は Anthropic のサーバ側ツールなので、ブラウザから呼んでも動く
（`web_search_20260209`。リードとサブ2・3が使う既定モデルは対応している）。

**歯止め:**
- `max_uses` で1タスクあたりの検索回数を制限する
- 教育系に限る運用（`allowed_domains`）を既定にし、担任が広げられるようにする
- 検索は**別料金**（トークンとは別に1検索ごとに課金される）。実装時に単価を確認して記録する
- 拾った情報は**出典URLを必ず併記**する。出典の書けない情報は捨てる

「データ」の意味が2通りありうる。ここは担任に確認したい（後述の質問3）。

## 5. 板書計画をどう出すか

板書は文章で書いても伝わらない。**図として描く**。
`bridge/figures.mjs` に `board` 型を追加する。

```
type: board
areas: めあて,問い,児童の考え,まとめ
widths: 2,3,4,3
notes: ...
```

黒板を横長の矩形として、区画を比で割り、各区画に見出しと中身を入れる。
図と同じく決定的に描くので、「右3分の1にまとめ」と書いたのに真ん中に来る、が起きない。

## 6. 成果物と保存先

```
01_教材/<教科>/<単元名>/
  00_単元計画.md        ← 単元のゴール・時間割り・各時間のゴールと問い
  01_ルーブリック.md    ← 下書き。3段階×観点
  02_資料.md            ← 出典URL付き
  03_板書_第1時.md      ← 板書図
  ...
```

1ファイルに詰め込まない。担任が直すときに、直したい部分だけ開けるようにする。

## 7. 段階

- **第1段**: リードのゴール決定＋問いづくり＋板書。ここまでで「明日から使える」
- **第2段**: ルーブリック（`00_共通/評価の根拠.md` と一次資料が要る）
- **第3段**: 資料集め（web_search）。単価を確認してから

第1段だけでも単元設計として成立する。第2・3段は根拠の置き場が整ってから。

## 8. 費用の見込み

同時異教材室（1時間分）が1回70〜90円。単元設計は
入力が増える（実態＋一次資料＋既存教材）ぶん、**1単元あたり300〜500円**を見込む。
web_search を使う回では、検索の従量課金が上乗せされる。
単元は週に1〜2回作るものなので、月あたりでは同時異教材室より小さい。

## 9. 担任に確認したいこと

1. **評価の根拠**（3節）— (a) 当該学年 / (b) 下学年適用 / (c) 特別支援学校の各教科の段階。
   児童によって違うなら、児童ごとに書く形にする
2. **単元の単位** — 7名が1〜4年に散っている。単元は
   (a) 同一題材・異目標で1本にまとめる / (b) 学年ごとに別々に立てる、どちらか
3. **「データ」の意味** — (a) 授業づくりの資料（実践事例・素材）/ (b) 児童の学習状況の記録
   （前回の正答率など）。(b) なら置き場と形式を決める必要がある
4. **黒板の形** — 大きさ（横幅）、常設の掲示（めあてカード、日付、時間割）、
   めあてとまとめを置く位置の決まり。あれば板書の型を先に固定できる
