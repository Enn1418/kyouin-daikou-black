# 職員室フロア — 全部屋を1画面に

担任の指摘（2026-08-23）:

> 各部屋が一つの空間に入り、それぞれが作業をしている様子が分かるようにしたい。
> 今のままでは毎回切り替えないといけないから煩わしい。
> 今後も部屋を増やしていく予定で設計してほしい。
> **作業の進捗、どこで何が行われているのかが分かることが大切。**

---

## 1. 何が問題だったか

3Dの職員室は「**1チーム = 1部屋。入る部屋を切り替える**」形だった。
部屋が6つに増えた時点で、これは成り立たなくなっている。

- どの部屋に何があるか、入ってみないと分からない
- 進捗を見るには切り替えが要る
- 部屋を増やすほど悪くなる（今後増やす前提なので、放置できない）

## 2. 二層に分けて考える

混ざりやすいので分けておく。**別の作業で、難しさが桁違い。**

| 層 | 何をするか | 状態 |
|---|---|---|
| **見え方** | 全部屋を1画面に俯瞰する。誰が何をしているか出す | **済**（`src/interface/FloorView.tsx`） |
| **同時実行** | 複数の部屋を本当に同時に動かす | **済**（下記4節） |

見え方だけ直しても、「切り替えの煩わしさ」は半分しか消えない。
ただし**先に見え方を作らないと、同時実行を作っても見る場所がない**ので、この順にした。

## 3. 済んだこと — フロア図

`viewMode: 'floor'` を追加し、**これを既定の画面**にした。

- `AGENTIC_SETS` から**部屋が自動で並ぶ**。チームを足せば部屋が増える。位置は手で決めない
- 部屋ごとに、机（＝担当）が1人ずつ並ぶ。リードは横幅いっぱい
- 担当の様子（待機／作業中／相談中／保留）を机の上に出す
- 進み具合の帯（完了/全件）と、**承認待ちの件数**を部屋の下に出す
- 毎日使う特支の部屋が主。もとから入っている英語のチームは「別棟」に畳む
- 部屋をクリックで担当を切り替え、「この部屋に入る」で3Dへ

ヘッダーの **フロア図 ⇄ 3Dへ** で行き来する。3Dは消していない。

### 承認待ちを目立たせている理由

担任が**手を動かさないと進まない唯一の状態**がこれ。作業中や完了は待てばよい。
色（琥珀）と「◯件 見てください」を、部屋の外から見えるところに置いた。

## 4. 済んだこと — 部屋ごとの状態と同時実行（2026-08-23）

以前の `coreStore` はプロジェクトが1本しか無く、担当も index（1〜5）で引いていたので、
別の部屋を開くと前の部屋の状態と衝突した。さらに部屋の切り替え時に
`resetProject()` を呼ぶ購読が居て、**部屋を替えるたびに仕事が消えていた**。これが煩わしさの正体。

いまの形:

```ts
// coreStore
rooms: Record<RoomId, RoomState>   // phase / tasks / 履歴 / ログ / 成果物 / 料金を部屋ごとに持つ
// uiStore
agentStatuses: Record<`${RoomId}:${index}`, AgentState>
```

- 部屋の中身に触る action はすべて末尾に `roomId?`（省略時はいま選んでいる部屋）
- `AgentBrain` / `PromptBuilder` / ツール群が「どの部屋の話か」を持って回る
- **`RoomManager`**（`src/core/rooms/RoomManager.ts`）が部屋ごとの `AgentSimulation` を持つ。
  部屋を切り替えても dispose しないので、**前の部屋の仕事は続く**
- 3D（SceneManager）はシミュレーションを「借りて覗く窓」になった。フロア図が全体の窓口
- チーム定義を編集したときだけ、その部屋のシミュレーションを作り直す（状態は coreStore 側に残る）

## 5. 見た目の方向 — 決定（2026-08-23）

担任の判断: **間取り図のまま。ただし家具等にも色を入れる。**

- 部屋の床を、その部屋の色でうっすら塗る（どの部屋か遠目で分かる）
- 備品を上から見た記号で置く: ホワイトボード（部屋色の枠）・本棚（部屋色の背表紙）・観葉植物
- 机は担当の色を天板の縁に入れる

ドット絵化は見送り。「進捗が分かること」が第一で、文字の読みやすさを落とさない範囲に留めた。

## 6. 画像生成について（調べた結果）

**Codex は画像を作れる。** 2026-04-16 の更新で画像生成が入り、
2026-04-21 に `gpt-image-2` が Codex CLI の既定になった。

ただし**この用途には直接は使えない**:

- Codex は**担任のPCで動く開発者向けのエージェント／CLI**であって、
  このアプリ（ブラウザで動く）の中から呼ぶ部品ではない
- アプリに画像生成を入れるなら、画像APIを直接叩く。
  **すでに Gemini の画像モデルが入っている**（設定画面に Gemini のキー欄がある）ので、
  新しい鍵を増やさずに済むのはこちら

### 線引き（重要）

- **板書・教材の図には使わない。** 数が合わないから決定的なコードで描いている（`bridge/figures.mjs`）。
  ここを画像生成に戻すのは後退
- **インフォグラフィック・挿絵・雰囲気の画像**なら向いている。
  保護者向けのおたより、掲示物、単元の導入で見せる絵など

### → 実装した（特支・広報室、2026-08-23）

`sn-koho`（`src/data/teacherAgents.ts`）。掲示物・おたより・インフォグラフィック担当。
広報ディレクター＋文面担当＋ビジュアル設計＋校正・安全確認の4人。
出力は Gemini の画像モデル（すでに設定画面にキー欄があるもの）。

原則を役割に埋め込んである:
- 文字が主役のもの（おたより本文）は Markdown → 印刷。画像モデルに日本語の文を描かせない
- 画像は文字なしの挿絵・背景・アイキャッチに徹する
- おたよりでは匿名IDすら書かず「子どもたち」等の集団の言い方にする（外に出るため）
- 板書・教材の図はこの部屋の仕事ではない

出典（2026-08-23 に確認）:
[Codex for (almost) everything — OpenAI](https://openai.com/index/codex-for-almost-everything/) /
[Codex CLI の画像生成と gpt-image-2](https://codex.danielvaughan.com/2026/04/27/codex-cli-image-generation-gpt-image-2-visual-development-workflows/)

## 7. 流れを見せる形に作り直した（2026-08-24）

担任の指摘:

> ワークフローの流れが分かるように矢印などを加えて、階層を示してほしい。
> たいせつなのは、見た目の可愛さを作ること。部屋の背景画像があると楽しい。

### 段（stage）で並べる

碁盤目に並べるのをやめ、**仕事が流れる順に上から下へ**置いた。

```
担任 → 1受付 → 2設計 → 3制作 → 4仕上げ → 5点検 → 6発信 → 教材フォルダ
```

段は `AgenticSystem.stage`（`src/data/floorStages.ts`）で決まる。**位置は今も手で決めない**
（§3 の約束）。部屋を足すときは段を1つ書くだけでよく、書き忘れても「制作」に出るので消えない。

段どうしの矢印は**案内図**であって、受け渡しの実装ではない。部屋は今も独立して動き、
次の部屋へ渡すのは担任の判断。ここを取り違えると「自動で流れるはず」と誤解させるので、
画面の下にもその旨を書いてある。

部屋の中は、まとめ役から担当へ枝が分かれ、できたらまとめ役に戻る形を線で描いた。

### 見た目 — §5 の決定を一部改めた

§5 では「ドット絵化は見送り、進捗の読みやすさが第一」としていた。今回もその第一は変えないが、
**やわらかいイラスト調まで寄せた**（担任の判断、2026-08-24）:

- 担当の顔を図形で描き、状態がそのまま表情になる（`src/interface/components/AgentFace.tsx`）。
  待機＝にっこり／作業中＝汗をかいて集中／相談中＝口が開く／保留＝困り顔。
  **画像にしないのは、状態4通り × 40人で160枚要るから。**「その子らしさ」だけを生成画像に任せる
- 段ごとに淡い色の床を敷き、承認待ちの部屋には朱色のはんこを出す

### 部屋の背景（生成画像）

`90_職員室/背景/<部屋id>.png` に置く。生成は Gemini の画像モデル、保存はブリッジの
`/asset`（`bridge/assets.mjs`）。文書用の `/file` は拡張子ホワイトリストで守っているので、
そこに PNG を通さず、**置き場所も名前もコード側が決める専用の口**にしてある。
渡せるのは種類と id だけなので、フォルダの外や別の拡張子には書けない。

- 生成の指示には必ず「文字を描かない」「中央を空ける」を入れる（§6 の線引きどおり）
- まだ描いていない部屋は、今までどおり部屋色の斜線のまま。キーが無くても壊れない
- ブラウザに貯めずファイルに残すのは、1枚10円ほどかかるため。履歴を消して作り直しになるのは高い
